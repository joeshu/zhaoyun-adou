# 需求实施计划

- [x] 1. 修正战场绘制层级和画布状态泄漏
  - 依据设计约束 D1“地图背景、道路、阵位、单位、HUD 必须保持独立视觉层级”，审查 `drawGame()` 中 `drawTerrainCutaway()`、`drawPath()`、`drawFormationPlatforms()`、`drawCell()`、`drawMapForeground()` 的调用顺序。
  - 在每个具有独立透明度、阴影或线型设置的绘制函数中补齐 `ctx.save()`、`ctx.restore()` 或显式状态复位，确保半透明和阴影不会污染后续单位、阿斗、合成栏和 HUD。
  - 将只属于战场的前景遮挡限制在 `UI_LAYOUT.playerField` 的有效范围内，保证合成栏 `UI_LAYOUT.handRows` 和操作栏 `UI_LAYOUT.actionBar` 保持独立。

- [x] 2. 收敛 2.5D 阵位和道路的几何表现
  - 依据设计约束 D2“连续阵位平台承担主要厚度，单个棋盘格只呈现平面和轻微落地关系”，调整 `drawFormationPlatforms()` 和 `drawCell()` 的透明度、厚度、边缘线和重叠区域。
  - 移除或压缩会形成独立高墙的单格侧面、重复底沿和高亮，保留统一阵排行为、可读边界和拖拽命中坐标。
  - 依据设计约束 D3“道路必须处于棋盘平面下方并被平台前沿正确遮挡”，调整 `drawPath()`、平台和格子的绘制顺序及道路前沿范围，消除道路穿过平台的视觉穿插。
  - 让敌我阵位使用统一的远近缩放规则和消失点参数，控制前后排的台面宽度、前沿深度与视觉密度，避免每排看起来处于同一距离。
  - [ ]* 2.1 编写阵位几何属性测试（属性 P1：所有阵位绘制尺寸保持正数且不改变原始交互坐标；属性 P2：平台厚度和单格附加厚度之和保持在移动端安全范围内；对应设计约束 D2、D4）

- [x] 3. 修复截图暴露的底部区域和控件遮挡

  - 检查 `drawAdouStand()`、`drawUnitGrounding()`、`drawMapForeground()` 的阴影与前景元素，确保单位、阿斗承台和边缘装饰不压住手牌内容或操作按钮。
  - 调整底部地形切面的颜色和透明度，使其提供纵深边界，同时保留手牌区背景与单位文字的对比度。
  - [ ]* 3.1 为 `UI_LAYOUT` 的战场、合成栏和操作栏编写边界测试（属性 P3：所有装饰绘制边界不得进入 `handRows` 和 `actionBar`；对应设计约束 D5）
